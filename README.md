# Psy_Lab — сайт для збору даних психологічного дослідження

Статичний сайт для анонімного онлайн-дослідження: респондент проходить анкету та чотири
опитувальники, одразу бачить обчислені результати й може зберегти їх у PDF, а знеособлені
дані потрапляють у Google Sheets.

**Стек:** GitHub Pages (сайт) + Google Apps Script (приймач) + Google Sheets (дані).
Усе безкоштовно, домен не потрібен.

| Методика | Пунктів | Шкали |
|---|---|---|
| DEBQ — Голландський опитувальник харчової поведінки | 33 | обмежувальна, емоціогенна, екстернальна |
| BSQ-34 — Опитувальник оцінки власного тіла | 34 | загальний показник |
| TAS-20 — Торонтська шкала алекситимії | 20 | загальний + DIF, DDF, EOT |
| STAI — Шкала реактивної та особистісної тривожності | 40 | реактивна, особистісна |

Разом 127 тверджень, орієнтовно 25–30 хвилин.

---

## Структура

```
index.html              єдина сторінка — усі екрани перемикаються скриптом
css/styles.css          оформлення, зокрема стилі друку для PDF
js/config.js            НАЛАШТУВАННЯ: адреса Apps Script, версія ключів, порядок методик
js/scoring.js           підрахунок балів (чисті функції, покриті тестами)
js/app.js               рушій опитування
methods/*.json          пункти, ключі та інтерпретація кожної методики
apps-script/Code.gs     код для Google Apps Script
tools/build_methods.py  перегенерація JSON з Word-файлу «Додатки.docx»
tests/scoring.test.js   контрольні приклади підрахунку
```

## Розгортання

### 1. Google Sheets + Apps Script

1. Створіть порожню таблицю Google Sheets.
2. **Розширення → Apps Script**, вставте вміст `apps-script/Code.gs`, збережіть.
3. **Deploy → New deployment → Web app**:
   - *Execute as:* **Me**
   - *Who has access:* **Anyone** — саме `Anyone`, а не `Anyone with Google account`,
     інакше респондентів проситиме увійти в обліковий запис Google.
4. Скопіюйте URL веб-застосунку.
5. Відкрийте цей URL у браузері — має повернутися `{"ok":true,...}`.

> **Після кожної зміни коду** випускайте нову версію:
> *Deploy → Manage deployments → олівець → Version: **New version***.
> Без цього веб-застосунок і далі виконує стару версію — це найчастіша причина
> «я все виправила, але нічого не змінилося».

### 2. Сайт на GitHub Pages

1. Створіть публічний репозиторій і завантажте в нього вміст цієї теки.
2. **Settings → Pages → Source: Deploy from a branch**, гілка `main`, тека `/ (root)`.
3. Через хвилину сайт буде за адресою `https://<нік>.github.io/<репозиторій>/`.

### 3. Звʼязати їх

У `js/config.js` впишіть URL з кроку 1:

```js
appsScriptUrl: 'https://script.google.com/macros/s/AKfy.../exec',
```

Поки це поле порожнє, сайт працює в демонстраційному режимі: усе рахується й
показується, але дані нікуди не надсилаються.

### Локальна перевірка

```bash
python3 -m http.server 8000
# відкрити http://localhost:8000
```

Просто відкрити `index.html` подвійним кліком не вийде — браузер блокує читання
JSON-файлів з `file://`.

## Дані в таблиці

Один рядок = один респондент, широкий формат — такий, який приймають SPSS, R і jamovi
без переформатування.

| Група колонок | Приклад | Що це |
|---|---|---|
| службові | `timestamp`, `session_id`, `scoring_version`, `duration_sec` | коли, ким (анонімно), якою версією ключів |
| анкета | `d_age`, `d_sex`, `d_bmi` | відповіді анкети, `d_bmi` рахується автоматично |
| сирі відповіді | `debq_q1` … `stai_q40` | бали **до** реверсивного перекодування |
| обчислені бали | `debq_restrained_score`, `tas20_total_score` | підсумки за шкалами |

Сирі відповіді зберігаються завжди — без них не порахувати альфу Кронбаха, не зробити
факторний аналіз і не перерахувати шкали, якщо в ключі знайдеться помилка.

Нові колонки Apps Script дописує сам: якщо ви додасте методику, її поля зʼявляться
праворуч, а старі рядки просто залишаться порожніми в цих колонках.

### Версія ключів

`scoring_version` у `js/config.js` пишеться в кожен рядок. Збільшуйте її щоразу,
коли змінюєте ключі або склад шкал — інакше після виправлення ви не відрізните
записи, пораховані до і після.

## Як додати або змінити методику

Методики описані декларативно — код чіпати не треба.

1. Створіть `methods/<id>.json` за зразком наявних.
2. Додайте `<id>` у масив `methods` в `js/config.js`.
3. Збільште `scoringVersion`.

Підтримувані способи підрахунку (`scoring.method`):

| Значення | Формула | Приклад |
|---|---|---|
| `sum` | сума балів за пунктами шкали | BSQ-34, TAS-20 |
| `mean` | сума ÷ кількість пунктів | DEBQ |
| `linear` | Σ(plus) − Σ(minus) + constant | STAI |

Реверсивні пункти перелічуються в масиві `reverse` і перекодовуються дзеркально
(`min + max − відповідь`). Для `linear` реверс не потрібен — його роль виконує формула.

### Перегенерація з Word-файлу

```bash
pip install python-docx
python3 tools/build_methods.py шлях/до/Додатки.docx
```

Скрипт витягує тексти пунктів дослівно з документа — так виключені помилки перенабору.
Ключі та межі інтерпретації задані в самому скрипті.

## Тести

```bash
node tests/scoring.test.js
```

48 контрольних прикладів: межові значення шкал, реверсивне кодування, збіг суми
субшкал із загальним балом, непересічність шкал, цілісність JSON-описів.
Проганяйте після будь-якої зміни ключів.

## Чутливі дані

Анкета містить запитання про діагнози, отримання психіатричної допомоги та способи
контролю ваги. Це **особлива категорія персональних даних**, навіть коли запис
анонімний, тому:

- поле «імʼя» з паперової версії анкети свідомо не перенесене — воно руйнує анонімність;
- усі запитання цього блоку необовʼязкові, респондент може їх пропустити;
- IP-адреса не збирається: Apps Script не передає її в таблицю, і код цього не робить;
- сторонніх скриптів аналітики на сайті немає.

Вступний екран містить звернення до учасників та інструкцію — текст заданий дослідницею
і відтворений дослівно. Розгорнутої форми згоди з чекбоксами на сайті немає; якщо комісія
з питань етики вимагатиме підтвердження безпосередньо перед проходженням, готовий
розширений текст лежить у проєкті (`claude/informed-consent.md`).

Інструкція для респондента живе тільки на вступному екрані й свідомо не дублюється
на екрані анкети.

На екрані результатів залишено попередження про те, що показники не є діагнозом, і
пропозицію звернутися до фахівця — його варто зберегти незалежно від того, де
отримується згода.
